# `store.py` — SQLite persistence

<span class="cs-kicker">collection_swarm/store.py</span>

The whole persistence layer lives in one file: 800 lines of straight
SQL through the standard library `sqlite3` module, with the result rows
hand-mapped back into Pydantic models. No ORM. No migrations framework
beyond an additive `_ensure_column` helper.

<dl class="cs-summary">
  <dt>Imports</dt><dd><code>sqlite3</code>, standard library, domain models</dd>
  <dt>Side effects</dt><dd>Creates the SQLite file and every table on construction</dd>
  <dt>Threading</dt><dd>Each call opens its own connection; safe across asyncio tasks under SQLite's serialized mode</dd>
</dl>

## `SimulationStore.__init__`

```python
def __init__(self, path: Path | str = "output/collection_swarm.sqlite") -> None:
    self.path = Path(path)
    self.path.parent.mkdir(parents=True, exist_ok=True)
    self._init_schema()
```

The store creates `output/` if it doesn't exist and runs `_init_schema()`
on every construction. Schema initialization uses `IF NOT EXISTS` for
all tables, so re-construction is idempotent.

## Tables

| Table                     | Purpose                                                                                  |
| ------------------------- | ----------------------------------------------------------------------------------------- |
| `runs`                    | One row per `SimulationResult`. Includes the transcript JSON and every Judgment field.   |
| `elo_ratings`             | One row per `(entity_type, entity_id, conversation_model, judge_model)` tuple.           |
| `elo_history`             | Append-only log of every `EloUpdate` ever applied.                                       |
| `tournaments`             | One row per `TournamentResult`.                                                          |
| `evolved_strategies`      | Strategies generated by the evolver, with lineage.                                       |
| `evolved_profiles`        | Profiles generated by the hardener, with lineage.                                        |
| `calibration_labels`      | Human-supplied calibration scores per `(transcript_id, metric, labeler_id)` tuple.       |
| `judge_prompt_variants`   | Snapshot of Judge prompts taken when calibration is invoked with `--optimize`.           |

The full DDL lives in `_init_schema`. Column types are intentionally
loose (most numerics are `REAL`, most identifiers are `TEXT`) so future
fields can land without a migration step.

### Schema evolution

```python
def _ensure_column(self, connection, table, column, definition) -> None:
    columns = {row["name"] for row in connection.execute(f"PRAGMA table_info({table})").fetchall()}
    if column not in columns:
        connection.execute(f"ALTER TABLE {table} ADD COLUMN {column} {definition}")
```

Adds `conversation_model` and `judge_model` to the Elo tables when they
predate the per-model-combo Elo split. New columns must be additive and
have defaults.

## Run persistence

| Method                       | Returns / does                                                              |
| ---------------------------- | --------------------------------------------------------------------------- |
| `save_run(result)`           | Single-row upsert.                                                         |
| `save_runs(results)`         | Bulk upsert via `executemany`. Used by the matrix runner.                  |
| `get_run(run_id)`            | Single-row lookup, raises `KeyError` on miss.                              |
| `list_runs(status="completed")` | All runs in `started_at` order, optionally filtered by status.          |

Runs are mapped to / from rows by `_run_row(result)` and
`_result_from_row(row)`. The transcript and constraint violations are
stored as JSON-encoded text columns; the helpers handle the
serialization round-trip.

## Analytical queries

The store doubles as the analytical query layer. The most-used queries:

| Method                                       | Output                                                                        |
| -------------------------------------------- | ------------------------------------------------------------------------------ |
| `get_strategy_comparison(profile_id)`         | `[StrategyStats]` ranked by `mean_payment_probability`.                       |
| `get_matrix_coverage()`                      | `{MatrixCell: completed_count}` for every Profile × Strategy × Model combo.   |
| `get_backfill_needed(target_reps, cells)`     | List of `MatrixCell` repeats needed to bring every cell up to `target_reps`. |
| `get_best_transcript(profile_id, strategy_id)` | The transcript with highest `payment_probability`, then `compliance_score`. |
| `get_all_transcripts(profile_id, strategy_id)` | Every completed transcript for a (Profile, Strategy) pair.                  |
| `get_compliance_summary(profile_id, strategy_id)` | Mean compliance + escalation across the pair.                            |
| `get_cost_summary()`                          | Aggregate token counts and dollars across every run.                          |
| `count_by_status()`                           | `{status: count}` map, e.g., `{"completed": 12, "failed": 3}`.                |
| `get_combo_runs(profile, strategy, …)`        | Per-pair runs sorted by ascending compliance, descending escalation, latest. |
| `get_performance_by(dimension)`               | `{id: {run_count, payment_probability, compliance_score}}` grouped by `profile_id`, `strategy_id`, `conversation_model`, or `judge_model`. |

Together they back every read-only API endpoint and the Playbook
generator.

## Elo persistence

| Method                                                                | What it does                                                |
| --------------------------------------------------------------------- | ----------------------------------------------------------- |
| `get_elo_ratings(entity_type=None, conversation_model=None, judge_model=None)` | Filtered list of current ratings.                  |
| `get_elo_rating(entity_type, entity_id, conversation_model, judge_model)` | Single rating; defaults to the seed `EloRating(rating=1500)` if missing. |
| `save_elo_update(update, tournament_id=None)`                         | Upserts the rating, increments win/loss/draw, appends history. |
| `get_elo_history(entity_id)`                                          | Time-ordered history for one entity.                        |
| `reset_elo_ratings()`                                                 | `DELETE FROM elo_ratings; DELETE FROM elo_history`.         |
| `save_tournament(result)`, `get_tournament(id)`, `list_tournaments()`  | Tournament header CRUD.                                     |

The win/loss/draw tally uses `DRAW_THRESHOLD = 0.05` from `models.py`:
scores within ±0.05 of 0.5 count as draws.

## Evolved Strategy / Profile persistence

| Method                                          | Purpose                                                          |
| ----------------------------------------------- | ----------------------------------------------------------------- |
| `save_evolved_strategy(strategy, lineage)`      | Upsert.                                                           |
| `get_evolved_strategy(strategy_id)`             | Single fetch.                                                     |
| `list_evolved_strategies(include_culled=False)` | Pairs of `(Strategy, StrategyLineage)`, ordered by generation.    |
| `cull_evolved_strategy(strategy_id)`            | Stamps `culled_at`, soft-removing it from the active pool.        |
| `get_evolved_strategy_pool()`                   | `{strategy_id: Strategy}` for active evolved strategies.           |
| `save_evolved_profile`, `get_evolved_profile`, `list_evolved_profiles`, `cull_evolved_profile`, `get_evolved_profile_pool` | Symmetric Profile API. |

The evolved pools are merged with the YAML pools in the runner so a
tournament can pit seed strategies against evolved ones in the same
match.

## Calibration & Judge variants

| Method                                            | Purpose                                                           |
| ------------------------------------------------- | ------------------------------------------------------------------ |
| `save_calibration_labels(labels)`                  | Per-metric upsert keyed by `(transcript_id, metric, labeler_id)`. |
| `list_calibration_labels()`                       | Re-aggregates rows back into `CalibrationLabel` objects.          |
| `save_judge_variant(system, transcript, calibration_score)` | Inserts a timestamped `judge_…` variant row.            |
| `list_judge_variants()`                           | All variants in reverse chronological order.                      |

The calibration labels table is keyed per metric so two labelers can
disagree on `compliance_score` for the same transcript without one
overwriting the other.

## Helper functions

`_run_row`, `_result_from_row`, `_elo_update_from_row`,
`_tournament_from_row`, `_strategy_from_evolved_row`,
`_strategy_lineage_from_row`, `_profile_from_evolved_row`,
`_profile_lineage_from_row` round-trip dataclasses to and from
`sqlite3.Row` objects. Keep them in sync with the `models.py` schema.

`_enum_value(value)` extracts the `.value` from a `StrEnum` member or
returns the raw string. Used in `_run_row` so `EndedBy` enums land as
plain strings in the table.

## Why no ORM

- The schema is small (eight tables) and stable.
- Every analytical query is one or two SQL statements; an ORM would add
  noise, not clarity.
- Tests mount the store against `sqlite3` directly and assert on raw
  rows. Skipping the ORM keeps the test surface small.

If the schema ever grows beyond a single file's worth of complexity, the
right move is to introduce SQLAlchemy + Alembic for migrations and split
the store by aggregate. We're not there yet.
